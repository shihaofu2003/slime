1引言

让大模型担任客服 Agent，不只是“会聊天”：它需要在几十轮对话中理解用户需求、检索政策文档、调用后端工具真正改变业务状态（改签一张机票、处理一笔退款、冻结一张遗失的银行卡），并妥善处理与用户的协作分工。tau-bench 系列基准正是为评估这类长程、工具驱动的 Agent 而设计：一个模拟用户与 Agent 多轮交互，环境执行工具并校验最终数据库状态，四次重复试验全部成功才算真正“学会”一个任务。

然而，对这类 Agent 做强化学习后训练，会立即遇到三堵墙：

  • 评测慢。一次忠实评测要运行数百条完整的“Agent—用户—工具”对话，逐条串行执行需要近 3 小时，严重拖慢迭代节奏。
  • 数据脏。开源 SFT 数据里混着失败对话与标注冲突，“整段对话最终成功”并不代表每一步操作都值得模仿；客服与用户的工具权限还经常混淆。
  • 奖励稀疏。几十轮操作结束才得到一个 0/1 任务奖励，哪一步做对、哪一步做错完全没有区分度；同一任务的 8 条采样轨迹全对或全错时，GRPO 甚至学不到任何组内信号。

本项目围绕上述问题，独立完成了从评测基建到数据、任务、训练系统、奖励设计再到模型汇集的完整后训练链路，如图 1 所示。六项工作按序衔接：前一项的产出是后一项的输入。

主要贡献：
  • 异步评测框架：Agent/User 共享推理池 + 跨领域弹性并发，三领域评测加速 4.88×、GPU-hours 降低 59.0%（§3.1）。
  • SFT 数据质量治理：从 33,531 条开源样本重建 30,376 条规范监督样本，根治了后续 RL 训练的行为坍塌（+28.00pp）（§3.2）。
  • Banking 任务构造：面向无数据领域程序化构造 647 个可回放验证的场景与 5,672 条 SFT 样本（§3.3）。
  • 异步 Agentic RL 系统：采样与训练重叠、环境多进程化，20 次更新提速 4.60×，GPU 利用率 21.5% → 76.2%（§3.4）。
  • 逐轮信用分配：基于状态进度的过程奖励，从同一 SFT 训练出四个领域专家（§3.5）。
  • 多教师 On-Policy 蒸馏：将四位专家汇集为单一学生模型，保留教师 93.4% 的任务完成能力（§3.6）。

2相关工作

2.1工具调用 Agent 与客服基准

tau-bench（Sierra）首次将“Agent ↔ 模拟用户 ↔ 工具环境”三元交互制度化，用最终数据库状态而非对话表面来评分，并要求多次重复试验以度量一致性（pass^k）；后续的 tau2-bench 扩展了更复杂的领域策略与双向工具协作。本项目使用其四领域版本（下称 tau3-benchmark，含 Airline、Retail、Telecom、Banking 共 197 个官方评测任务），并针对无训练数据的 Banking 领域自行构造训练任务（§3.3）。

2.2大模型后训练与 Agentic RL

SFT 是后训练的起点，但其效果高度依赖数据质量——本项目的治理工作（§3.2）表明，数据配方差异在后续 RL 中会被放大为“坍塌与不坍塌”的分野。强化学习方面，PPO/RLHF 奠定了偏好优化范式；GRPO（DeepSeekMath）以同组轨迹的相对优势替代价值网络，因实现简洁成为 Agentic RL 的常用基线。本项目在 GRPO 之上叠加逐轮过程奖励（§3.5），并处理了异步采样带来的策略滞后问题（§3.4）。

2.3长程任务的信用分配

结果奖励（outcome reward）只有终局一个标量，无法区分几十轮操作中各自的贡献。过程奖励（process reward）与步骤级信用分配试图为中间步骤提供信号，但多数做法依赖额外训练的打分模型或人工标注。本项目不引入任何打分模型：利用环境可回放的特性，用参考解法的目标数据库定义状态势函数，以相邻决策的势差作为逐轮局部奖励（§3.5）。

2.4知识蒸馏与 On-Policy Distillation

经典序列级蒸馏让学生模仿教师生成的文本；on-policy distillation（如 GKD）则在学生自己采样的轨迹上计算教师信号，使学生为“自己会犯的错误”获得反馈。本项目将这一思想扩展为多教师设置：四个领域专家作为冻结评分服务，按任务领域路由，对学生实际生成的每个 token 构造 reverse-KL 优势，并与异步训练流水线共存（§3.6）。

2.5RL 训练系统

slime（THUDM）、AReaL（蚂蚁）、verl（字节）等框架为 LLM 强化学习提供 Megatron + Ray + SGLang 的分布式底座。本项目基于 slime 实现：持续采样 producer 与 Trainer 重叠、真实生成 token 与逐 token 概率的对齐、环境交互多进程化，以及超长轨迹的重采样机制（§3.4）。

3方法

3.1异步 benchmark 评测

问题一次模型验证要运行三领域 400 条完整对话轨迹。旧流程逐领域、逐轨迹串行，一条轨迹等待用户模拟器回复时，其他轨迹无法填补 Agent 推理的空闲；串行基线耗时 174–230 分钟。

方法将 Agent 与用户模拟器部署为共享推理池（2 个 TP1 Agent 副本 + 3 个 TP2 User 副本），三个领域进程内的轨迹线程并发交错执行；每个领域持有跨进程并发信号量，先完成的领域自动把槽位让给慢领域；按逐请求计时定位瓶颈后，将 User 路由从 cache-aware 改为 round-robin，使三个 User 副本均匀分担负载。

结果三领域 100 题 × 4 次试验的端到端耗时由 174.26 min 降至 35.71 min（4.88×），GPU-hours 降低 59.0%。该框架随后支撑了全部四领域（788 条轨迹/轮）的官方评测。

3.2Agentic SFT 数据质量治理

问题AReaL 开源的三领域 SFT 数据有 33,531 行，但审计发现：约四分之一的训练行来自失败或标注冲突的对话；工具返回被写成纯文本、客服与用户的工具权限不分；一轮塞进多个工具调用，与“每轮至多一个调用”的领域策略直接冲突。“整段对话最终成功”不代表每一步都值得模仿——终局标签无法区分局部错误与有效步骤。

方法不依赖终局标签，逐类审计并从源数据重建官方原生格式：仅保留标签一致的双成功对话；将一轮多调用展开为逐轮原子监督（后续调用的上下文插入前一调用的真实工具返回）；隐藏用户侧工具调用但保留其自然语言报告；只监督每行最后一个 Assistant 目标，历史消息全部 mask；按真实渲染后的长度过滤超长样本。另以本地 27B 模型做逐目标双轮语义评审做消融验证。

结果治理的价值在后续 RL 中被放大验证：在完全相同的 100 次 GRPO 更新下，用未治理数据初始化的训练中途行为坍塌（持续复制工具说明、形成空参数调用，pass@1 跌至 22.75%），治理后初始化的训练保持 50.75%（+28.00pp，配对 95% CI [+21.75, +34.38]）。

3.3Banking 任务构造

问题Banking 领域没有任何现成训练数据；官方任务又过难——一条任务往往同时要求“找政策—读事实—确认实体—判断资格—验证身份—发现工具—协同操作—核对状态”，4B 模型官方成功率仅 2.58%，直接采样几乎采不到成功示范，GRPO 同组轨迹全失败、缺少组内差异。

方法将复杂客服流程拆解为事实抽取、知识检索、规则判断、工具执行、用户协作等原子能力，按“单项能力—能力组合—完整工作流”设计 7 种任务形态（L1–L6），覆盖 15 类银行业务与正常办理、拒绝办理、动态工具、多实体等情形。程序与大模型分工：程序生成全新的客户、账户、交易、初始数据库与判分条件（与官方测试实例严格隔离），大模型仅负责把用户开场改写自然。每个任务的参考解法都在真实环境中逐步回放，确认可执行且判分正确。

结果最终构造 647 个场景（训练/开发/挑战 = 542/75/30），参考回放 647/647 全部通过；采集模型自主交互的成功轨迹，用 27B 模型提议删除冗余步骤、再经语义复核与环境重放，产出 5,672 条 SFT 样本（同批轨迹 token 总量 −58.7%）。训练后官方 97 题 pass@4 由 4.12% 升至 9.28%。

3.4异步 Agentic RL 训练系统

问题RL 阶段模型要现场与用户交互、调用工具：一条轨迹可达数十轮，少数慢轨迹拖住整批训练；工具返回与历史不断增长，单条超长对话会让 log-prob 前向的 [T,V] logits 直接撑爆显存；即使推理 GPU 有空闲，单进程环境计算（数据库序列化、状态比较）受 GIL 限制，Trainer 仍长时间无数据可用。

方法基于 slime（Megatron + Ray + SGLang）实现异步流水线：持续采样 producer 推进多条独立对话，同一任务的 8 条轨迹组成 GRPO 组，完成即入队、Trainer 按完成顺序消费，空出名额即时补充新任务；超长轨迹单独重采样（至多两次）而非截断，保证训练上下文与真实生成一致；记录每回合真实 prompt/输出 token、逐 token 行为概率与策略版本，以截断重要性采样（TIS）修正异步策略滞后；经 profiling 定位 CPU/GIL 瓶颈后，将环境交互与奖励计算拆至 4 个 CPU 进程并行，并缓存数据库快照减少重复计算。

结果相同初始化、相同预算（20 次更新、batch 128）下，采样与训练耗时由 370.22 min 降至 80.46 min（4.60×），Generator GPU 平均利用率由 21.54% 升至 76.22%；该流水线支撑了后续四领域专家（140 次更新、17,920 条轨迹）与 160 次更新的 OPD 蒸馏训练。

3.5基于状态进度的逐轮信用分配

问题终局二元奖励无法区分“工具和实体都找对、只差一次写入”与“调用不存在的工具”——两者同样记 0；GRPO 又把整条轨迹的优势广播到所有 token，正确查询与错误执行共享同一训练方向。

方法利用环境可回放的特性构造状态势函数：用相同初始状态回放参考动作得到目标数据库，定义 Φ(s) = −distance(s, s_target)（到目标状态的字段差异数取负；环境断言任务则取已满足断言比例）。每次 Agent 决策后读取真实状态，相邻决策的势差作为逐轮进度奖励，以 γ=0.98 折扣累积为 return；在同任务 K=8 条轨迹内，按“当前数据库相对初态的变化量”分桶做组内归一化，得到逐轮优势 Q，与 GRPO 终局优势相加；对格式错误、调用不存在工具、越权调用等行为施加局部惩罚，并通过消息索引映射到产生错误的 Assistant 轮次。

结果从同一四领域 SFT 出发（独立优化器），训练并选定 Airline、Retail、Telecom、Banking 四位领域专家；官方 197 题评测下，各领域 pass@1 较 SFT 分别提高 11.25 / 1.88 / 4.38 / 0.52pp。

3.6多教师 On-Policy 蒸馏

问题四位领域专家各有所长，但线上只能部署一个模型；序列级蒸馏让学生模仿教师文本，而学生真正需要的是在自己会走的上下文、自己会犯的错误上获得反馈。

方法将四位专家部署为冻结的评分服务。学生照常与用户、环境自主交互（on-policy），按任务领域路由到对应专家；专家对学生实际生成的每个 token计算 logprob，与训练侧重算的当前学生 logprob 作差，构成逐 token 的 reverse-KL 优势——教师比学生更认可的输出被强化，不被认可的被抑制。成功与失败轨迹均参与蒸馏（任务奖励仅用于监控）；以 TIS 修正异步采样的策略滞后，并用总预取回压（buffer32）把平均策略滞后从 8.29 次更新压到 1.03。

结果完成四领域 160 次更新的纯 OPD（K=1、batch 16，共 2,560 条轨迹，覆盖 97.7% 任务源），经官方评测选定 Update 80 学生：在四个领域分别保留对应教师 93.0%、95.9%、92.8%、83.3% 的任务完成能力，总体保留率 93.4%。

4实验结果

4.1评测协议

全部模型质量结论来自官方评测协议：Airline / Retail / Telecom / Banking 共 197 个任务（20/40/40/97），每题 4 次试验共 788 条轨迹；固定 Qwen3.6-27B 用户模拟器（关闭思考），Agent temperature 0.6、单次输出上限 1,200 tokens、max_steps 200，Banking 使用 BM25 检索。三个指标分别回答不同问题：pass@1 衡量平均单次成功率，pass@4(any) 衡量任务覆盖（四次至少成功一次），pass^4 衡量一致性（四次全部成功）。

4.4消融与负结果

  • 学习率行为对照：2e-6 / 3e-6 / 5e-6 三组均完成 100 次更新且无 NaN，但 5e-6 出现明显行为退化（重复工具调用 0.14 → 2.56 次/轨迹，pass@1 18.50%）——“数值不炸”不等于“行为稳定”。
  • 数据复筛消融：27B 模型逐目标双审删除 675 条可疑样本后，匹配更新数的重训对照反而退步（pass@1 −3.63pp），故保留 30,376 条配方。
  • 严格同步/异步对照：20 次更新提速 1.060×，100 次更新为 0.977×——本项目的 4.60× 收益来自供给与 CPU 瓶颈治理，而非“异步”本身。
  • turn credit v2 受控对照：对 outcome-only 为 +2.50 / +3.50 / +4.00pp（95% 配对 CI 均含 0），越界工具轨迹 14.92% → 2.95%；因未按预设规则胜过 v1，当次保留 v1，后续演进为状态进度配方。
  • Banking 全域仍弱：官方 97 题 pass@1 约 4%，合成训练集上的高成功率（82.38%）不能外推到官方任务。

5讨论与局限

  • 评测种子与选型不确定性。四领域专家与 Update 80 学生的选型基于单一评测 seed（300）上的多 checkpoint 比较，尚无独立 seed 复验选型优势；简历级结论均标注为点估计。
  • 一致性与覆盖率的权衡。多项实验中 pass@4(any) 的提升伴随 pass^4 回落（如 Retail 专家 +10.00 / −5.00pp），“能做成更多任务”与“每次都做成”需要分别优化。
  • Banking 占比与难度。Banking 占官方 197 题的 49.2%，其低成功率大幅拖累总体数字；该领域的进展更接近“从零搭建数据管线”，能力提升仍有限。
  • 数字口径边界。4.88× 来自历史三领域评测协议；+28.00pp 是“治理 vs 未治理初始化”的对照收益而非 RL 算法本身；93.4% 是教师绝对成绩的保留率（SFT 初始化本身已达教师的 91.3%）。

6结论

本项目走通了一条面向长程客服 Agent 的完整后训练链路：先把评测变快（4.88×），再把数据变干净（根治 RL 行为坍塌）、为空白领域造出任务（647 场景全回放通过），随后让 RL 训练本身变快（4.60×）、让奖励信号变细（逐轮状态进度），最后用多教师蒸馏把四位领域专家汇集回一个可部署的 4B 学生（保留 93.4% 能力）。每一步都以固定官方协议做对照，并如实记录了未胜出的消融与口径边界。后续方向：更强的信用分配、Banking 领域能力提升，以及跨训练 seed 的稳定性验证。
