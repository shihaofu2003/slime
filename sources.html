02 · SFT 数据治理

依据 project_docs/02_AReaL三领域SFT数据质量治理.md 第 6–8 节。源数据 33,531 行 / 2,499 段对话；双成功候选 24,816 行；工具展开后 31,679 个 targets；删去 1,303 个超长 targets，得到 30,376 行。源行、对话与展开后 targets 是不同计数单位。

Raw-all 与 Processed SFT 对照使用三领域 100 题、每题 4 trials、seeds 300/301。pass@1 为 53.125% / 55.75%，pass@4(any) 为 82.50% / 81.00%，pass^4 为 23.00% / 28.00%。整体 pass@1 差值的配对 95% CI 为 [−2.12, +7.38] pp，pass^4 为 [−1.50, +11.00] pp，均包含 0。

两种初始化继续同配置 vanilla GRPO 100 次更新后，pass@1 为 22.75% / 50.75%。这轮证据支持特定配置下的行为稳定性改善；表示处理、数据分布和标签过滤一起变化，不能分离单项贡献。后来删除 675 个 targets 的额外双审没有赢得匹配重训，未纳入最终配方。

最终四领域 SFT 合并 30,376 行三领域数据与 5,672 行 Banking 数据，共 36,048 行。从原始指令模型开始，2 epochs、batch16、LR1e−5 余弦下降到 1e−6，完成 4,506 次更新，使用 iter4505。这里的四领域总体 27.92% 不能与三领域专项 55.75% 直接比较。

实验：tau2-sft-official-native-expanded、tau2-sft-raw-all-max16384/FINAL_REPORT.md、tau2-rl-sft-raw-vs-processed-vanilla-grpo/RESULTS.md、tau2-sft-areal3-banking-simplified-full-20260920。

03 · Banking 任务构造

依据 project_docs/03_Banking任务构造.md。最终场景覆盖 15 类业务，训练 / 开发 / 挑战为 542 / 75 / 30，共 647 个独立场景；参考回放 647 / 647 通过。训练集中采集 1,914 条成功轨迹，整理后保留 1,651 条完整轨迹，导出 5,672 个 Assistant-target 样本，覆盖 530 个训练任务。

官方派生诊断题退出训练来源。合成任务仍共用业务模板、接口和政策体系，开发与挑战集也有与训练集共用的模板。参考回放成功不能替代模型自主成功，不能把合成留出集成绩写成官方 97 题成绩。

Banking 专项 SFT 的固定官方对照：成功轨迹 10 → 17 / 388，至少一次成功的任务 4 → 9 / 97，四次全成功均为 1 / 97。因此增量为 +1.80 / +5.15 / 0.00 pp。这个专项 checkpoint 与四领域混合 SFT4505 不同。

04 · 异步 Agentic RL

依据 project_docs/04_异步Agentic_RL.md，重点是 Airline 流水线优化与对应质量对照。jobs 21033 / 21168 同 SFT4673、batch128、外部 Qwen3.6 User，在前 20 次更新窗口内用时 370.22 / 80.46 分钟。起点是首次采样入池，终点是第 20 次 optimizer 完成；不包含启动与最终清理。

平均每步等数据 868.65 / 142.63 秒，Trainer 计算 81.85 / 82.57 秒；Generator GPU 利用率 21.54% / 76.22%。利用率来自 8 张训练 GPU，不含另设的 4 张 User GPU。阶段时间有重叠。

同 iter19 的 Airline 成绩为 52.50 / 80.00 / 25.00% → 53.75 / 80.00 / 30.00%。工程调度、缓存、并发与任务采样共同变化，因此这是整套流水线收益。严格同步/异步的独立 20 步对照只有 1.060×，100 步对应训练进程时间为 269.42 / 275.73 分钟。

计时源：tau2-airline-db-count-tuning/reports/speed-diagnosis/long30-timeout60/speed_comparison.json。质量：reports/quality-diagnosis/README.md。实现：continuous.py、agent_tokens.py、train_async.py。

05 · 状态进度信用分配

依据 project_docs/05_Credit_assignment.md 与 progress.py、reward_postprocess.py。势函数是到参考目标 DB 的负字段差异数；用于标准化分桶的计数则是当前 DB 相对初态发生变化的记录数。这两个量不可互换。

按轮计算势函数差，以 γ = 0.98 累积后续进度，再在同任务、同变化记录数的桶内标准化。优势合成为 outcome GRPO + progress + format，两项附加权重均为 1。格式项每轮最多 −0.1。主线与 Vanilla 都过滤 outcome 全同的 K8 组。

同为 SFT4505 初始化、LR2e−6、140 次更新、16×K8、相同任务池与 User。iter139 状态进度配方相对 Vanilla 的总体差值 +1.27 / +2.54 / +0.51 pp。单训练 run、单评测 seed，不声称统计显著；没有独立消融分桶和格式项。

Airline 诊断显示，在 7 道不应写 DB 的题、28 条 trial 中，expert29 成功 27 条，Mix139 成功 20 条。训练池此类任务 53 / 1,148，Mix 实际入训此类组 43 / 1,211；这些结果支持检查业务覆盖与边界退化。

实验：tau2-mix-rl-sft4505-b128-20260925，诊断 airline_diagnosis/README.md。专家：tau2-domain-experts-sft4505-b128。

06 · 当前双教师 OPD

当前结果依据 tau2-opd-mix139-airline-20260929/README.md。学生初始化与非 Airline 教师均为 2026-09-25 Mix RL iter139，Airline 教师为同源 expert iter29。训练共 160 次更新，最终选择 iter59，即第 60 次更新后的权重。

当前训练使用 2,524 任务的打乱池、K1、batch16、LR2e−6、训练 / 采样 seeds1234/42、current-student OPD 与 TIS [0,2]。总缓冲 32 组，4 个环境进程，policy_lag = −1，无固定滞后步数上限。资源为训练 8 GPU、固定 User 4 GPU、两位教师共 4 GPU。

历史 buffer 对照来自 tau2-opd-current-buffer-ab/ANALYSIS_AND_NEXT.md：受限 / 无上限的平均滞后为 1.03 / 8.29，实测最大为 4 / 20 次更新。无上限组经历故障恢复，任务分数没有明确全面胜负。LR 对照来自 tau2-opd-bounded-lr-20260922/RESULTS.md：在 matched seeds1235/43 下，2e−6 / 5e−6 的三领域两评测 seed 平均 pass@1 为 55.125 / 49.75%，差值的任务配对 95% CI 为 [+1.50, +9.375] pp，未覆盖训练 seed 波动。

当前 iter59 的非 Airline 成功轨迹数由 214 / 708 变为 211 / 708。98.6% 是 两个三域加权 pass@1 的比值，不是新模型的绝对成功率，也不表示三个领域分别都保持 98.6%。

旧 project_docs/06_多教师OPD.md 记录的是 2026-09-23 四教师、从 SFT 初始化的实验。其 93.4% 保留率和 Update80 选择属于历史结果，不是当前模型。错误初始化的 2026-09-29 旧运行也不纳入本次对比。
