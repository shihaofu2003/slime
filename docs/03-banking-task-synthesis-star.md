# 第三份记录：tau2 Banking 任务合成

## S：背景（Situation）

Tau2 Banking 原始集合共有 97 条任务，覆盖信用卡申请、身份验证、返现与奖励、
交易争议、信用额度、账户开户与销户、ATM 费用、卡片遗失、PIN 锁定、储蓄利息和
推荐奖励等 15 类银行业务。原始任务通常同时包含知识检索、事实抽取、实体绑定、
业务判断、身份验证、动态工具发现、Agent/User 工具协作和数据库写入。直接把完整
任务作为一个训练样本时，最终二元奖励很难说明失败发生在哪一步，也无法给正确的
局部行为分配 credit。

2026-09-06 修正：这 97 条任务将全部用于最终 benchmark 评测。因此，由其中任一任务
派生的完整任务或原子任务都属于评测派生数据，不能用于训练。此前“按
`source_task_id` 切分后进入训练”的判断不成立，因为不存在未被最终评测使用的源任务。

因此，这一阶段的目标不是自由生成更多相似对话，而是把原始任务表示为
“证据节点 → 判断节点 → 动作节点 → 状态节点”的依赖图，再从经过验证的节点构造
不同难度的诊断探针，并提炼后续新场景所需的能力模板。97 条源任务中有 3 条参考链不能在当前环境稳定回放：
`task_051` 的写请求与初始状态冲突，`task_077` 使用当前不存在的 Agent 工具，
`task_083` 的四个争议动作缺少必需参数。它们保留在源任务清单中，但没有被强行
修补后混入合成池；实际扩展覆盖其余 94 条源任务。

## T：任务（Task）

任务合成需要同时满足以下目标：

- 覆盖 94 条可回放源任务和全部 15 类 Banking 业务，而不是只扩展少数容易任务。
- 将完整任务拆成知识、检索、决策、单动作、受控组合和完整工作流，逐步增加难度。
- 每条任务保留来源、业务类别、能力标签、参考文档、参考动作和成功条件。
- 原子任务不向 Agent 泄漏 gold 答案，也不继承与当前子任务无关的 User 工具。
- 所有任务先通过静态检查和真实 Tau2 Banking 环境参考回放，再进行模型生成。
- 使用同一个 `/mnt/afs/models/Qwen3.8-27B` 分别承担 Agent 和 User。Agent 开启
  xhigh thinking，User 关闭 thinking；生成协议失败必须单独恢复，不能记成业务错误。
- 区分任务规格、模型成功轨迹和训练用途：当前 benchmark 派生规格只用于诊断；后续
  训练任务必须使用新的场景、实体、状态、用户表达和动作组合。

## A：行动与合成原则（Action）

每条源任务先拆成六部分：业务目标、证据与文档、实体和初始状态、推理与判断、
动作及其 requestor、成功检查与最终状态。在此基础上派生六种任务形态：

| 形态 | 诊断边界 |
|---|---|
| `evidence-given` | 提供一篇指定文档，只抽取一个决定性事实 |
| `retrieval-only` | 在知识库中找到目标文档，不执行银行操作 |
| `decision-only` | 提供证据和状态，只完成业务判断 |
| `single-action` | 提供已解析目标和正确前置状态，只完成一个动作 |
| `two-skill-composition` | 只组合两个已经拆开的原子能力 |
| `full-composition` | 历史 benchmark 回放探针，仅作诊断，禁止训练 |

难度通过组合能力形成，并尽量一次只增加一个主要复杂因素：

| 等级 | 结构 | 主要目标 |
|---|---|---|
| L1 | 一篇给定文档、一个事实、无工具 | 事实抽取 |
| L2 | 从语料中检索一个目标文档 | 查询构造和相关性判断 |
| L3 | 单次决策或一个带参数动作 | 资格判断、动作选择和参数构造 |
| L4 | 两个原子能力或较短完整流程 | 受控组合 |
| L5 | 4–8 篇文档、一次追问或恢复 | 中等工作流 |
| L6 | 多实体、多写操作、动态工具和用户协作 | 端到端综合能力 |

L1–L6 是课程阶段，不是用固定权重计算的难度分数。实际任务仍保留文档数、实体数、
动作数、分支、对话和工具归属等原始维度。

第一批把 94 个源任务各构造成六种形态，共 564 条任务。第二批 Scale V2 根据依赖图
继续细化每一个节点，生成 933 条逐事实 `evidence-given`、933 条对应的
`retrieval-only` 和 874 条带正确前置状态的逐动作 `single-action`，共 2,740 条。
这两批数据现在统一视为 benchmark 派生诊断集，不是合成训练集。

合成过程遵循以下约束：

- **源任务落地**：文档、实体、动作名称、参数、requestor 和 DB 状态都来自原始任务
  与真实环境，不由语言模型凭空补全。
- **Gold 不泄漏**：固定首条 User 请求只给章节、行号、表格键或输出占位符，不包含
  正确答案本身。
- **交互有边界**：原子任务只暴露当前评分动作需要的 User 工具；首次实质回答后
  User 返回 `###STOP###`，避免无关后续操作造成 DB 假失败。
- **成功契约明确**：每条任务记录必需文档、动作、参数、回复事实和预期状态变化，
  评分仍使用 Tau2 的 ACTION、COMMUNICATE、DB 和环境检查。
- **验证与能力分离**：参考回放失败说明任务规格有问题；Qwen3.8 得 0 说明模型没有
  满足成功契约，两类问题分别统计。
- **失败不静默丢弃**：初次推理若耗尽 token 或没有最终消息，保留首次统计并提高
  token/context 单独恢复，只有形成有效轨迹后才计入模型正确率。

17 个零 GPU 单元测试覆盖任务唯一性、来源映射、User 工具边界、终止协议、节点级
扩展和恢复结果覆盖。两批任务随后分别完成真实环境 schema 校验和参考回放；第一批
564 条、第二批 2,740 条均为零合成任务错误。第一批 94 条和第二批 933 条参考 BM25
查询也都能命中目标文档。

## R：规模、质量与阶段结论（Result）

当前共形成 **3,304 条可执行任务规格**：

| 批次 | 构造方式 | 任务数 | Qwen3.8 精确成功 |
|---|---|---:|---:|
| 第一批 | 94 个源任务 × 六种形态 | 564 | 329（58.33%） |
| Scale V2 | 933 个事实 + 933 个检索 + 874 个动作节点 | 2,740 | 2,163（78.94%） |
| 合计 | 94 个源任务的原子节点和组合版本 | **3,304** | **2,492（75.42%）** |

第一批最初有 16 条生成或上下文协议失败。通过 16K output、262K context、必要时
TP2，以及最难样本的 32K compact-history 恢复后，16 条都得到有效轨迹；最终只有
563 条 `user_stop` 和 1 条 `max_steps`，没有 infrastructure error。Scale V2 的
2,740 条轨迹全部以 `user_stop` 结束，同样没有 infrastructure error。

合并后的逐等级结果为：

| 等级 | 任务数 | 成功数 | 成功率 | 当前用途判断 |
|---|---:|---:|---:|---|
| L1 | 1,027 | 636 | 61.93% | 新训练数据应重点覆盖事实能力 |
| L2 | 1,027 | 1,025 | 99.81% | 检索能力已接近饱和，后续少量生成 |
| L3 | 1,062 | 785 | 73.92% | 新训练数据的主要难度区间 |
| L4 | 104 | 19 | 18.27% | 新任务扩容前先改善局部 credit |
| L5 | 31 | 14 | 45.16% | 作为新中等工作流的配比参考 |
| L6 | 53 | 13 | 24.53% | 作为新完整工作流的难度参考 |

L4 的成功率低于 L5 并不表示等级顺序错误。L4 中有 94 条严格的
`two-skill-composition`，整体只有 14/94（14.89%）成功；L5 是数量较小、组成不同的
完整工作流。等级描述的是结构，后续还需要依据实测结果继续校准。

第一批六种形态的结果进一步说明了能力边界：`retrieval-only` 为 93/94（98.94%），
`decision-only` 为 84/94（89.36%），`evidence-given` 为 58/94（61.70%），
`single-action` 为 48/94（51.06%），`full-composition` 为 32/94（34.04%），
`two-skill-composition` 为 14/94（14.89%）。Scale V2 把动作继续拆到节点级后，
`single-action` 达到 653/874（74.71%），说明逐节点拆分有效；但 Assistant 发起的
动作检查通过率为 90.50%，User 发起的动作只有 42.16%，User 工具协作仍是明确短板。

从诊断规格角度看，当前数据质量较高：3,304 条都能执行、成功契约可检查、参考轨迹
可回放。难度结果仍能指导新数据配比：L2 检索已接近饱和，L1/L3 是主要能力缺口，
L4–L6 暴露组合与长程 credit 问题。但此前划分的 1,121 条行为锚点、2,089 条 GRPO
学习前沿和 2,492 条 SFT/教师候选现已全部撤销训练资格。

按 `source_task_id` 切分不能解决这里的泄漏，因为 94 个源场景全部属于最终 benchmark。
现有 3,304 条任务和 2,492 条成功轨迹统一放入 `benchmark_derived_diagnostic`，禁止进入
SFT、GRPO 和 OPD。下一轮从 Banking 知识库、工具 schema、数据库 schema 和业务约束
生成独立场景，不读取逐条 benchmark gold 来实例化任务；新任务不得复用 benchmark 的
用户请求、实体、初始状态、required-document 组合、动作参数或动作链。完整工作流只能
由这些新场景的已验证节点组合产生。
